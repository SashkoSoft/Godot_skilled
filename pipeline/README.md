# Пайплайн контента: Godot-сессия ↔ три сессии-исполнителя

Общее место обмена между сессиями Claude Code. Все общаются **только через файлы в этой
папке**, каждая работает в **своём клоне** репозитория, единственный канал — git.

## Кто есть кто

| Роль (`assignee`) | Что делает | Своя инструкция | Спеки |
|---|---|---|---|
| **godot** | пишет игру, ставит задания, принимает работу | `CLAUDE.md` в корне | — |
| **houdini-assets** | модели, текстуры, материалы, VFX | [`HOUDINI_LOOP.md`](HOUDINI_LOOP.md) | `ASSET_SPEC.md` |
| **houdini-anim** | скелетные анимации (KineFX, APEX) | [`HOUDINI_ANIM_LOOP.md`](HOUDINI_ANIM_LOOP.md) | `ANIM_SPEC.md` + `ASSET_SPEC.md` |
| **comfyui** | изображения, флипбуки, UI, концепты, SFX | [`COMFYUI_LOOP.md`](COMFYUI_LOOP.md) | `ASSET_SPEC.md` + `AUDIO_SPEC.md` |

Ссылка на инструкцию — единственное, что нужно дать новой сессии: каждый файл
самодостаточен, включая команду клонирования и проверку окружения.

## Схема папок

```
pipeline/
  tasks/
    open/           ← Godot кладёт задания      (исполнители: забирать свои)
    in_progress/    ← исполнитель взял в работу (Godot: не трогать)
    done/           ← выполнено                 (Godot: принимает)
    blocked/        ← нужны уточнения           (Godot: отвечает)
    TEMPLATE.md     — шаблон задания
  delivery/
    <task-id>/v1/   ← файлы + RESULT.md
    <task-id>/v2/   ← доработка, v1 остаётся рядом для сравнения
  QUEUE.md          — доска состояния, генерируется status.sh
  status.sh         — пересобрать доску; `--for <роль>` — показать задания одной роли
  new_task.sh       — создать задание из шаблона (для Godot-сессии)
  ASSET_SPEC.md · ANIM_SPEC.md · AUDIO_SPEC.md — требования к результату
```

**Папка = статус, поле `assignee` = адресат.** Дублировать состояние где-то ещё не надо:
рассинхрон дороже удобства.

## Маршрутизация: как исполнители не мешают друг другу

Все задания лежат в одной очереди `tasks/open/`, но у каждого в шапке указан адресат:

```yaml
---
id: task-0012
assignee: houdini-anim
...
---
```

Каждая сессия берёт **только свои** задания и не трогает чужие. Отдельные папки под роли
не заводим специально: так задание можно переназначить, поправив одну строку, а не
перекладывая файлы.

Посмотреть очередь одной роли:

```bash
bash pipeline/status.sh --for comfyui
```

## Жизненный цикл задания

```
   Godot                          исполнитель
   ─────                          ───────────
   open/  ───(свой assignee)───►  in_progress/
                                       │  делает
                                       ▼
   done/  ◄───────────────────    delivery/<task-id>/v1/ + RESULT.md
     │
     ├─ принято  →  status: accepted, ассет уходит в игру
     └─ на переделку → open/ (revision+1, раздел «Правки»)
```

1. **Godot-сессия** создаёт задание: `bash pipeline/new_task.sh <роль> <slug>` —
   скрипт возьмёт свободный номер и подставит шаблон. Затем описывает требования и пушит.
2. **Исполнитель** на своей итерации берёт самое старое из **своих**, переносит в
   `in_progress/`, ставит `status: in_progress` и `started:`.
3. Кладёт результат в `delivery/<task-id>/v<N>/` вместе с `RESULT.md`.
4. Переносит задание в `done/`, ставит `status: done` и `finished:`, обновляет доску
   (`bash pipeline/status.sh`), делает один коммит и `push`.
5. **Godot-сессия** делает `git pull`, прогоняет
   `bash tools/asset_check/check.sh pipeline/delivery/<task-id>/v<N>` и пишет вердикт
   в раздел «Приёмка»:
   - **принято** → `status: accepted`, файл остаётся в `done/`;
   - **на переделку** → конкретные пункты в разделе «Правки», `revision+1`,
     `status: open`, файл возвращается в `open/`. Исполнитель кладёт доработку в `v2/`.

Новое задание заводится, только если нужен **другой** ассет, а не другая версия этого.

Если задание непонятно или невыполнимо — исполнитель переносит его в `blocked/`,
пишет вопросы в соответствующем разделе; Godot-сессия отвечает там же и возвращает в `open/`.

## Git: правила, чтобы четыре сессии не подрались

- Каждая сессия начинает итерацию с `git pull --rebase` и заканчивает **одним** коммитом.
- Префикс в сообщении = роль: `houdini-anim: task-0012 walk cycle — done`.
- Push отклонён → `git pull --rebase` → push ещё раз. Стороны пишут в разные файлы,
  поэтому ребейз проходит без конфликтов.

Кто какой файл пишет:

| Файл | Кто пишет |
|---|---|
| `tasks/open/*` | Godot (создаёт, возвращает на переделку) |
| перенос между папками, `status`, `started`, `finished` | исполнитель, которому адресовано |
| раздел «Приёмка» и «Правки» в задании | Godot |
| раздел «Вопросы», `tasks/blocked/*` | исполнитель |
| `delivery/**` | исполнитель (Godot только читает) |
| `QUEUE.md` | никто вручную — генерируется `status.sh` |

Единственный файл, который трогают двое, — само задание. Но пишут они в **разные разделы**
и в разное время (Godot — когда задание уже в `done/`), так что git сливает это сам.
Конфликт в `QUEUE.md` чинится перегенерацией.

## Вес файлов

Обычный git, без LFS:

- один файл — **до 50 МБ**, вся доставка по заданию — **до 200 МБ**;
- не класть кэши симуляций, `.bgeo`-сиквенции, чекпойнты моделей, промежуточные рендеры,
  `.hip` тяжелее 20 МБ;
- не влезает — положить уменьшенную версию, полную оставить локально и написать об этом
  в `RESULT.md`. Тогда решим, включать ли Git LFS.
