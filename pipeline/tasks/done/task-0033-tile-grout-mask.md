# task-0033 — Плитка: маска шва для процедурного нойза

> Требования к сдаче: `pipeline/ASSET_SPEC.md`, договор — `pipeline/VARIETY.md`

## Зачем это в игре

Шов в принятых наборах (`tile-bath`, `tile-floor`, `tile-kitchen`) — идеально
ровная сетка, одинаковая ширина и глубина на всём тайле. С полутора метров
это читается печатным узором, а не швом затирки: в реальной плитке шов гуляет
по ширине, местами темнее от грязи, местами выкрошен.

Движок умеет добавлять шум сам — шейдер `antitile.gdshader` уже накладывает
макро-вариацию и per-тайл переокраску, — но ему нужно **знать, где именно
проходит шов**, а не выискивать его по перепаду яркости альбедо (это ненадёжно
и ломается на текстурах с рисунком). Нужна отдельная маска.

## Требования

- **Что именно:** по одной карте на каждый из трёх принятых наборов плитки:
  `tile_bath_seam_1k.png`, `tile_floor_seam_1k.png`, `tile_kitchen_seam_1k.png`.
- **Формат:** grayscale, тот же размер и та же UV-развёртка, что у albedo —
  пиксель в пиксель. **Белое — шов, чёрное — плитка.** Не бинарная маска:
  внутри полосы шва — не плоская заливка 255, а собственный лёгкий разброс
  (0.7…1.0), чтобы после нашего шума шов не остался идеально однородным —
  именно на это жалуемся.
- **Ширина шва в маске** — не обязана совпадать с видимой шириной шва на
  альбедо (визуальную ширину мы уже приняли), но должна идти строго по
  ЦЕНТРУ тех же линий: маска — это разметка «где», а не «как выглядит».
- **Никакого запекания эффектов в саму карту** — ни грязи, ни темноты, это
  будет накладываться в движке по маске отдельно. Только форма.

## Формат сдачи

```
tile-bath/tile_bath_seam_1k.png
tile-floor/tile_floor_seam_1k.png
tile-kitchen/tile_kitchen_seam_1k.png
```

Кладутся В ТЕ ЖЕ папки, что и остальные карты набора. `preview.png` — маска
поверх albedo с прозрачностью 50%, чтобы было видно совпадение линий.

## Приёмка (заполняет Godot-сессия после проверки)

### v1 — 2026-09-01

- [x] Три карты, размер и UV совпадают с albedo — по превью линии маски
      (бирюзовый оверлей) совпадают с реальным швом на всех трёх наборах,
      включая перекрестье; по RESULT.md совпадение по построению (общее
      выражение решётки), замерено на одном столбце.
- [x] Белое по центру шва, не бинарно — есть внутренний разброс — 0.702…1.000
      внутри полосы, разброс 0.072, идёт вдоль линии шва, а не пятнами.
- [x] В маске нет запечённой грязи/темноты, только форма — тело плитки
      измерено по всем 64 плиткам каждого набора, максимум среднего 0.00000.

Записана линейно (без гамма-коррекции) — это уже учтено в шейдере,
`tex_seam` объявлен без `source_color`, как `tex_id`/`tex_orm`. Файлы
скопированы в `game/assets/textures/tile-{bath,floor,kitchen}/`,
`use_seam` включится в `_tex_st()` автоматически по факту наличия файла.
