# Технические требования к ассетам для Godot 4.7

Для Houdini-сессии: **знать Godot не нужно**, достаточно соблюдать этот файл.
Все пункты сверены с официальной документацией Godot 4.7 (`docs/godot-docs/`),
ссылки на статьи даны в конце.

## Общие правила

- **Единицы:** 1 unit Godot = **1 метр**. Дверь ≈ 2.1, персонаж ≈ 1.8, этаж ≈ 3.
- **Оси:** Y — вверх, −Z — «вперёд» (та же система, что в Houdini по умолчанию, Y-up).
- **Начало координат:** в точке, за которую объект логично ставить в мир —
  у пола для мебели и построек, в центре масс для того, что летает и катится.
- **Масштаб трансформаций** запечён в геометрию (scale = 1, rotation = 0 на экспорте).
- **Имена файлов:** `snake_case`, только латиница, без пробелов:
  `rock_mossy_01.glb`, `lava_albedo_2k.png`.
- **Никаких пробелов и кириллицы** в именах файлов и материалов — Godot их переварит,
  но пути в коде станут хрупкими.

## 3D-модели

**Формат: glTF 2.0, бинарный `.glb`** — рекомендованный движком формат обмена.

| Что | Требование |
|---|---|
| Основной формат | `.glb` (геометрия + материалы + текстуры в одном файле) |
| Альтернатива | `.gltf` + отдельные текстуры — если нужно править текстуры отдельно |
| Допустимо | `.obj` (только статика без PBR), `.dae` |
| Нежелательно | `.fbx` — импортируется через ufbx, но glTF надёжнее |
| Не поддерживается | `.hip`, `.bgeo`, `.abc`, `.vdb` — движок их не читает |

- **Нормали** экспортировать явно (не полагаться на пересчёт при импорте).
- **UV:** канал 0 — основные UV. Канал 1 (UV2) — только если ассет пойдёт под
  запечённый lightmap; иначе не нужен.
- **Треугольники**, без n-гонов. Полигонаж под назначение:
  пропс на переднем плане — до ~20k tris, фон/декор — до ~2k, мелочь для инстансинга — сотни.
- **Коллизия:** если форма сложная, класть рядом упрощённый меш с суффиксом `-col`
  (например `rock_01-col`) — Godot автоматически делает из него коллизию при импорте.
  Простые формы (ящик, сфера, капсула) коллизией снабжаются в коде, отдельный меш не нужен.
- **Материалов на модель — минимум**, в идеале один. Каждый лишний материал = отдельный
  draw call; для декора, который будет инстансироваться сотнями, это критично.
- **Анимации** — в том же `.glb`, с осмысленными именами клипов (`idle`, `run`, `attack`).
  Скелет: без масштабирования костей.

## Текстуры

**Формат: `.png`** (8 бит на канал) для всего обычного, `.exr` — для HDR.

| Тип | Формат | Цветовое пространство |
|---|---|---|
| Albedo / BaseColor | `.png` | **sRGB** |
| Normal | `.png` | линейное, **OpenGL-конвенция (X+ Y+ Z+)** |
| Roughness, Metallic, AO, Height, Mask | `.png` | линейное (grayscale) |
| ORM (упакованная) | `.png` | R = AO, G = Roughness, B = Metallic |
| HDRI-панорама для неба | `.exr` или `.hdr` | линейное, latlong |
| Флипбуки эффектов | `.png` с альфой | sRGB |

- **Нормали — только OpenGL-стиль (Y+).** DirectX-нормаль (Y−) даст вывернутое освещение.
  Если генератор выдаёт Y−, инвертируйте зелёный канал на своей стороне и напишите
  об этом в `RESULT.md`.
- **ORM-упаковка предпочтительна**: одна текстура вместо трёх, движок читает её напрямую
  (`ORMMaterial3D`). Если упаковать нельзя — кладите три отдельных grayscale-файла.
- **Размеры — степень двойки**: 512 / 1024 / 2048 / 4096. По умолчанию **2048**;
  8K не присылать без явной просьбы.
- **Тайлящиеся текстуры** обязаны быть бесшовными по обеим осям; в `RESULT.md` указать
  реальный размер тайла в метрах (например «1 тайл = 2 м»).
- **Альфа:** обычная (не premultiplied), если в задании не сказано иначе.
- **Шероховатость не шумит.** Проверено на принятых наборах: высокочастотный шум
  в канале Roughness даёт локальные глянцевые пятна, и под точечным светом
  поверхность искрит белыми точками — это читается как брак рендера, а не как
  износ. Для матовых поверхностей (бетон, штукатурка, обои, линолеум) держать
  Roughness ≥ 0.6 и размах по тайлу не больше 0.25, Metallic — ноль.
- **Нормаль на полу — мягкая.** Свет лампы падает на пол под скользящим углом
  и вытаскивает любой резкий рельеф в блики. Крупный рисунок (шов плитки, стык
  доски) нужен, зерно и микроцарапины — нет.
- Не присылать `.tga`, `.psd`, `.tif` — движок их не импортирует.

## Эффекты (VFX)

Движок **не читает VDB и не проигрывает симуляции**. Огонь, дым, взрывы, магию
отдавать одним из трёх способов:

1. **Флипбук (спрайт-лист)** — сетка кадров в одном `.png` с альфой.
   Стандарт: 8×8 кадров, кадр 256×256 (итог 2048×2048).
   В `RESULT.md` обязательно: **сколько кадров по горизонтали и вертикали** и
   сколько из них заполнено — движку это задаётся числами.
2. **Меш-эффект** — геометрия для шейдерной анимации (ударная волна, портал, трейл):
   `.glb` с чистой UV-развёрткой, «время жизни» закладывать в UV или вершинный цвет.
3. **Набор частиц-текстур** — отдельные спрайты (искра, дым, осколок) плюс описание,
   как они должны двигаться. Движение соберём на стороне движка.

Для «атласа» из нескольких эффектов — отдельный `.png` на эффект, не мешать в один файл.

## Небо и окружение

- Панорама: `.exr`, latlong (2:1), 4096×2048 или 2048×1024.
- Кубмапа, если нужна: порядок граней X+, X−, Y+, Y−, Z+, Z− (Y+ — вверх, Z− — вперёд).

## Что класть в доставку

В `pipeline/delivery/<task-id>/v<номер ревизии>/` (`v1/` — первая сдача, `v2/` — доработка
по разделу «Правки»; прошлые версии остаются на месте для сравнения):

```
rock_mossy_01.glb
rock_mossy_01_albedo_2k.png
rock_mossy_01_orm_2k.png
rock_mossy_01_normal_2k.png
preview.png            ← простой рендер: как это выглядит
RESULT.md              ← обязательно
source/rock.hip        ← если < 20 МБ и есть смысл переиспользовать
```

`preview.png` экономит целый круг переписки: по нему сразу видно, то ли сделано.

## `RESULT.md` — что в нём должно быть

```markdown
# task-0007 — камни, мшистые

## Файлы
| Файл | Что это | Размер |
|---|---|---|
| rock_mossy_01.glb | меш, 3.4k tris, 1 материал | 820 КБ |
| rock_mossy_01_orm_2k.png | R=AO, G=Roughness, B=Metallic | 2.1 МБ |

## Параметры
- Габариты: 1.8 × 1.2 × 1.6 м, пивот в основании.
- Тайл текстуры: 2 м.
- Нормаль: OpenGL (Y+).

## Отклонения от задания
- Просили 4 варианта — сделано 3, четвёртый выходил слишком похожим на второй.

## Что можно докрутить
- Мох управляется параметром `moss_amount` в .hip, могу выдать версию посуше.
```

Раздел **«Отклонения от задания»** обязателен, даже если он пустой («нет») — по нему
Godot-сессия сразу понимает, надо ли что-то переделывать.

## Чего избегать (частые причины возврата)

- Модель в сантиметрах — объект приезжает в 100 раз больше нужного.
- Пивот в центре объекта у того, что ставится на пол.
- DirectX-нормаль вместо OpenGL.
- Текстуры не степень двойки (1500×1500) — движок импортирует, но сжатие и мипмапы хуже.
- Десяток материалов на одну модель.
- Дублирование геометрии «на всякий случай» (LOD-ы одним файлом, скрытые копии).
- Файлы с пробелами и кириллицей в имени.
