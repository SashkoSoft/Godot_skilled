# Инструкция ComfyUI-сессии (изображения и звук)

**Это твоя полная инструкция. Начни отсюда — больше ничего искать не надо.**

Ты — сессия Claude Code, которая генерирует в ComfyUI **изображения и звук** для игры
на Godot: текстуры, спрайты, флипбуки эффектов, элементы интерфейса, концепт-арт и SFX.
Игру пишет другая сессия («Godot-сессия»), она ставит задания файлами, ты возвращаешь
файлами, всё через git. Godot тебе ставить и знать не нужно.

Твоя роль в пайплайне называется **`comfyui`**. Рядом работают ещё две сессии:
`houdini-assets` (модели, текстуры, VFX) и `houdini-anim` (скелетные анимации).
Каждая берёт только задания со своим `assignee`.

## Что сделать в самом начале (один раз)

1. **Склонировать репозиторий** в свою папку, отдельную от папок других сессий:

   ```bash
   git clone git@github.com:SashkoSoft/Godot_skilled.git
   ```

   Без SSH-ключа: `git clone https://github.com/SashkoSoft/Godot_skilled.git`
   (для `push` понадобится токен — скажи об этом пользователю сразу).

2. **Прочитать спеки** — по ним принимают работу:
   - `pipeline/ASSET_SPEC.md`, раздел «Текстуры» и «Эффекты» — форматы, размеры,
     каналы, флипбуки;
   - `pipeline/AUDIO_SPEC.md` — целиком, если задание про звук.

3. **Проверить окружение**: запускается ли ComfyUI в API-режиме, есть ли нужные модели,
   получается ли сохранить результат в `.png` и в `.wav`/`.ogg`. Чего не хватает —
   сказать пользователю сейчас, а не на первом задании.

4. **Рабочее держать вне репозитория**: чекпойнты, latent-кэш, промежуточные выдачи,
   тысяча вариантов одного и того же. В git уходит только выбранный результат.

Корневой `CLAUDE.md` и всё вне `pipeline/` — не твоё, это правила Godot-сессии.

## Одна итерация лупа

1. `git pull --rebase` — это твой единственный канал связи.

2. Смотри `pipeline/tasks/open/`. Бери **только файлы с `assignee: comfyui`** в шапке.
   - Своих нет → **ничего не делать**, тихо завершить итерацию. Чужие задания не трогать.
   - Есть → взять одно, с наименьшим номером.

3. Перенести файл в `pipeline/tasks/in_progress/`, поставить `status: in_progress`
   и `started: <дата>`. В работе держать одно задание.

4. Сделать по разделу «Требования» задания и по спекам.
   Если `revision: 2` и больше — это возврат на доработку, читай раздел «Правки»
   и правь **ровно перечисленное**.

5. Положить результат в `pipeline/delivery/<task-id>/v<номер ревизии>/`
   (прошлые версии не удалять — по ним сравнивают):
   - готовые файлы (`.png`, `.ogg`, `.wav`);
   - `RESULT.md` — что сделано, параметры, **обязательный** раздел «Отклонения от задания»;
   - `workflow.json` — граф ComfyUI, если результат осмысленно повторять или докручивать.
     Это ваш аналог исходника, он маленький и очень окупается.

6. Перенести задание в `pipeline/tasks/done/`, поставить `status: done` и `finished:`,
   затем `bash pipeline/status.sh` (доску руками не править).

7. Не можешь выполнить — в `pipeline/tasks/blocked/`, `status: blocked`, в разделе
   «Вопросы» написать конкретно, чего не хватает («не указан размер тайла»,
   «просят бесшовную текстуру 4К, модель даёт швы — резать или брать другой подход?»).

8. Один коммит на итерацию: `comfyui: task-0015 ui icons — done`, затем `git push`.
   Если push отклонён — `git pull --rebase` и push ещё раз.

## Памятка по изображениям

1. **`.png`** — всё обычное, **`.exr`** — только HDR (панорамы неба).
   Не `.jpg` (артефакты на текстурах), не `.psd`, не `.tif`.
2. **Размеры — степень двойки:** 512 / 1024 / 2048 / 4096. По умолчанию 2048.
3. **Тайлящиеся текстуры** обязаны быть бесшовными по обеим осям; в отчёте — сколько
   метров занимает один тайл.
4. **Карты по каналам:** albedo — sRGB; roughness/metallic/AO — оттенки серого;
   ORM — одна текстура, где R = AO, G = Roughness, B = Metallic.
   Карты нормалей генеративными моделями лучше **не** делать: если очень нужно —
   пометить в отчёте, что она сгенерирована, а не снята с геометрии.
5. **Флипбуки эффектов** — сетка кадров в одном `.png` с прозрачностью, стандартно 8×8
   по 256 px (итог 2048×2048). В `RESULT.md` **обязательно**: сколько кадров по горизонтали
   и вертикали и сколько из них заполнено.
6. **Прозрачность** — обычная альфа, не premultiplied, если не сказано иначе.
7. **UI и иконки** — с запасом прозрачных полей, одинаковый оптический размер в наборе.

## Памятка по звуку

Полностью — в `AUDIO_SPEC.md`, коротко:

1. **SFX — `.wav` 16 бит 44.1 кГц**, музыка и длинный эмбиенс — **`.ogg`**.
   Ничего кроме WAV / Ogg / MP3 движок не читает.
2. **Моно** для всего, что звучит из точки в мире (шаги, удары, механизмы).
   Стерео — только музыка, глобальный эмбиенс, интерфейс.
3. **Без тишины в начале**, пик −3…−6 dBFS, без клиппинга.
4. **Часто повторяющиеся звуки — набором из 3–5 вариантов** (`step_dirt_01..04`).
5. Зацикленные — бесшовные, со словом `loop` в имени.

## Правила

- Не трогать задания с чужим `assignee` и ничего вне `pipeline/`.
- Не переоткрывать закрытые задания: вернуть в работу может только Godot-сессия.
- **Один результат, а не галерея.** Выбирать лучший вариант — твоя работа; если сомнения
  реальные, положи максимум два и объясни разницу в `RESULT.md`.
- Писать честно, чем сгенерировано и что подправлено руками: от этого зависит,
  сможем ли мы повторить результат для соседнего ассета.

## С кем ты общаешься

**Только через файлы.** Пользователь — не твой собеседник по задачам: он запустил тебя
и смотрит со стороны. Все решения принимает Godot-сессия.

- Непонятно задание, противоречие, нужен выбор → задание в `tasks/blocked/`, вопрос
  в разделе «Вопросы». Не спрашивай в чате — в лупе этого никто не прочитает.
- Замечание по спеке, идея, «так было бы удобнее» → раздел в `RESULT.md`.
- Сломалось окружение (нет лицензии, не запускается софт, git не пускает) → **вот тут**
  скажи пользователю прямо и останови итерацию: это единственный случай, когда нужен он.

Ответ на вопрос придёт файлом: задание вернётся в `open/` с заполненным разделом.
