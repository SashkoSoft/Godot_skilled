# Инструкция Houdini-сессии (работа в `/loop`)

Ты — сессия, которая делает ассеты в Houdini для игры на Godot. Задания приходят
файлами, результат ты отдаёшь файлами. С Godot ты не работаешь и знать его не обязана:
все требования к файлам — в `ASSET_SPEC.md`.

## Одна итерация лупа

1. **Синхронизация** (только если работаешь в отдельной копии репозитория):
   `git pull --rebase`.

2. **Есть ли работа?** Смотри `pipeline/tasks/open/`.
   - Пусто → **ничего не делать**. Не придумывать себе задания, не «улучшать» прошлые
     доставки, не переписывать документы. Тихо завершить итерацию (noop).
   - Есть файлы → взять **один** с наименьшим номером.

3. **Взять в работу:** перенести файл в `pipeline/tasks/in_progress/`, в шапке поставить
   `status: in_progress` и `started: <дата>`. Одновременно в работе держать **одно** задание.

4. **Сделать ассет.** Всё по разделу «Требования» задания и по `ASSET_SPEC.md`.
   Если по ходу выясняется, что задание противоречиво или требует того, чего Houdini не
   отдаст в нужном формате, — см. пункт 7.

5. **Отдать результат** в `pipeline/delivery/<task-id>/`:
   - сами файлы (`.glb`, `.png`, `.exr`);
   - `preview.png` — простой рендер, «как это выглядит»;
   - `RESULT.md` по образцу из `ASSET_SPEC.md`, с обязательным разделом
     «Отклонения от задания»;
   - `source/*.hip`, если файл меньше 20 МБ и его есть смысл переиспользовать.

6. **Закрыть:** перенести задание в `pipeline/tasks/done/`, поставить `status: done`
   и `finished: <дата>`, обновить `QUEUE.md`.

7. **Если не можешь выполнить:** перенести в `pipeline/tasks/blocked/`, поставить
   `status: blocked`, в разделе «Вопросы» задания написать **конкретно**, чего не хватает
   («не указан размер тайла», «просят VDB-дым, но движок его не читает — отдать флипбуком?»).
   Не гадать и не делать «как-нибудь» — блок дешевле, чем ассет, который выкинут.

8. **Зафиксировать** (если отдельная копия репозитория): один коммит на итерацию —
   перенос задания + доставка + `QUEUE.md`.
   Сообщение: `houdini: task-0007 lava texture — done`. Затем `git push`.

## Правила

- **Не трогать** `tasks/open/` кроме как забирая оттуда файл, и никогда не редактировать
  задания, лежащие в `open/` — их пишет Godot-сессия, вы можете писать одновременно.
- **Не трогать** ничего вне `pipeline/`. Код игры, документация, скилы — не твоя территория.
- **Не переоткрывать** закрытые задания. Если по готовому ассету пришли правки — это будет
  новое задание со ссылкой на старое.
- **Один ассет — одно задание.** Не докладывать в доставку то, чего не просили: лишние
  варианты стоят времени, а выбирать всё равно будет Godot-сессия.
- В `RESULT.md` писать честно: что не получилось, где срезали угол, что осталось грубым.
  Приукрашенный отчёт стоит дороже плохого ассета — по нему принимают решения, не глядя
  в файлы.

## Пример полного цикла

Было: `pipeline/tasks/open/task-0007-lava-texture.md`.

```
git pull --rebase
# переносим в работу
git mv pipeline/tasks/open/task-0007-lava-texture.md pipeline/tasks/in_progress/
# ... работа в Houdini, экспорт ...
# кладём результат
pipeline/delivery/task-0007-lava-texture/lava_albedo_2k.png
pipeline/delivery/task-0007-lava-texture/lava_orm_2k.png
pipeline/delivery/task-0007-lava-texture/lava_normal_2k.png
pipeline/delivery/task-0007-lava-texture/preview.png
pipeline/delivery/task-0007-lava-texture/RESULT.md
# закрываем
git mv pipeline/tasks/in_progress/task-0007-lava-texture.md pipeline/tasks/done/
git add pipeline && git commit -m "houdini: task-0007 lava texture — done" && git push
```

Стало: задание в `done/`, файлы в `delivery/`, строка в `QUEUE.md` обновлена.

## Ритм лупа

Задания появляются нерегулярно — Godot-сессия ставит их по мере того, как доходит до
соответствующей части игры. Нормально, что несколько итераций подряд ничего нет: пустая
итерация должна быть дешёвой и молчаливой. Не надо на всякий случай проверять старые
доставки или переделывать то, что уже принято.
