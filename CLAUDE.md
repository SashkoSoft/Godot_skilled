# Проект: игра в браузере

>  **Если ты сессия-исполнитель** (делаешь контент, работаешь в `/loop`) — этот файл не про тебя.
> Твоя инструкция по роли:
> `houdini-assets` → **`pipeline/HOUDINI_LOOP.md`** ·
> `aimocap` → **`pipeline/AIMOCAP_LOOP.md`** ·
> `comfyui` → **`pipeline/COMFYUI_LOOP.md`**.
> Всё остальное в репозитории читать не нужно, трогать — тем более.
> **Форматы сдачи не менялись:** glTF/`.glb`, PNG, WAV. Движок к ним отношения не имеет.

## Куда делся Godot

Проект развёрнут на **веб** 13 сентября 2026. Причина одна и она решающая:
пользователь должен видеть результат сразу, а цикл «правка → пересборка → скриншот»
в Godot слишком медленный для подбора вида.

Годот **не удалён и не заброшен насовсем** — `game/`, `Godot_v4.7-stable_win64*.exe`
и `docs/godot-docs/` лежат как есть. Экспорт обратно — открытый вопрос, к которому
вернёмся, если понадобится. Пока туда ничего не дописывается.

Что переехало даром: **вся принятая библиотека**. 41 модель `.glb` и 27 наборов
текстур грузятся браузером без конвертации, скининг из мокапа — тоже. Проверено
на `railing_flight.glb`. Что НЕ переехало: логика на GDScript (`plan3d.gd`,
`tower.gd`, навигация, боты, лифты) — её пишем заново на JS. Данные обмеров
(`game/plan_traced.json`, `plan_left.json`) остаются в силе.

## Движок

**three.js 0.186**, завендорен в `web/vendor/three/` — сайт не должен зависеть от
сети. Подключается через import map в `web/index.html`; `three/addons/` указывает
туда же.

```bash
python web/serve.py            # http://127.0.0.1:8080/web/
python web/serve.py 9000       # другой порт
```

Сервер отдаёт **корень репозитория**, а не `web/`: модели лежат в `game/assets/`,
и копировать их во вторую папку значило бы завести второй источник правды ровно
того сорта, на котором проект уже один раз сломался.

## Как проверять свою работу

Не сваливать проверку на пользователя. Есть скриншот-харнесс — тот же цикл,
что был в Godot:

```bash
python web/shot.py                          # общий ракурс -> web/shot.png
python web/shot.py --view 3 --out C:/tmp/kerb.png
python web/shot.py --debug 1                # нормаль цветом
python web/shot.py --no-bump                # A/B без микрорельефа
```

Рядом с PNG кладётся `.log` с консолью браузера. **Ошибки выводятся в кадр**
через HUD — иначе провал сборки шейдера виден только чёрным экраном.

Оговорка: WebGL в headless идёт программным ANGLE. Содержание кадра честное,
**скорость — нет**, производительность так мерить нельзя. Замер — только
секундомером в настоящем браузере, парой «с фичей / без фичи»
(скил `measurement-sanity`).

## Структура

| Где | Что |
|---|---|
| `web/index.html` | страница, import map |
| `web/src/main.js` | сцена, свет, туман, камера, цикл, загрузка ассетов |
| `web/src/street.js` | раскладка улицы в метрах |
| `web/src/surface.js` | материал покрытия + `PRESETS` (цвета всех покрытий) |
| `web/src/shaders/surface.glsl` | процедурное покрытие — **источник правды** |
| `web/vendor/three/` | three.js локально |
| `tools/shader_web/` | стенд покрытий (артефакт) + `sync.py` |

**Покрытие — это `MeshStandardMaterial` с инъекцией через `onBeforeCompile`,
а не свой шейдер со своим светом.** Если считать свет внутри, улица и загруженные
`.glb` окажутся под двумя разными моделями освещения и никогда не сойдутся: одна
и та же стена будет разной на модели и на процедурной плите рядом. Покрытие даёт
только альбедо, шероховатость и нормаль — остальное общий PBR, тени, туман, тонемап.

## Стенд покрытий

Артефакт на claude.ai: живой редактор `surface.glsl` с мгновенной пересборкой,
ползунками материалов и ракурсами, совпадающими с игрой. Годится только для
**процедурных поверхностей** — там браузер гоняет ровно тот же файл.

```bash
python tools/shader_web/sync.py    # подтянуть шейдер и PRESETS в стенд
```

Правило, по которому решается, что вообще можно вынести на отдельную страницу:
**может страница показать сам артефакт из репозитория или только имитацию?**
`.glsl` и PNG — сам файл, можно. Свет, туман, композиция кадра — нельзя никогда:
страница начнёт врать, а числа будут подбираться под враньё.

## Две поверхности доставки

- **Игра** — обычный веб-проект в репозитории, локальный сервер, публикация на
  GitHub Pages (orphan-ветка, `main` не пушится — см. память по проекту).
- **Артефакты** — однофайловые инструменты и превью. Артефакт ≤ 16 МБ и **не может
  подгрузить `.glb` из репозитория**: внешние ресурсы только с нескольких CDN.
  Смешивать нельзя — как только страница начнёт грузить модели, она перестанет
  быть артефактом.

— **движка не касаются, применимы как есть**. `godot-codefirst` и

приёмка глазами) по-прежнему верны, команды запуска — нет.

## Контент делают три сессии-исполнителя

Ассеты приходят от отдельных сессий Claude Code, работающих в `/loop`, каждая в своём
клоне репозитория. Обмен — только через файлы в `pipeline/` (протокол — `pipeline/README.md`).
**Разворот на веб пайплайна не касается:** форматы нейтральные, спеки в силе.

| Роль (`assignee`) | Что делает | Спека |
|---|---|---|
| `houdini-assets` | модели, текстуры, материалы, VFX | `pipeline/ASSET_SPEC.md` |
| `aimocap` | скелетные анимации (мокап из видео, GVHMR) | `pipeline/ANIM_SPEC.md` |
| `comfyui` | изображения, флипбуки, UI, концепты, SFX | `pipeline/ASSET_SPEC.md`, `pipeline/AUDIO_SPEC.md` |

Со стороны этой сессии:

- **подключить сессии:** готовые команды — `pipeline/START_SESSIONS.md`;
- **создать задание:** `bash pipeline/new_task.sh <роль> <slug> "<заголовок>"` — подставит
  свободный номер, `assignee` и ссылку на нужную спеку; дальше описать «Зачем это в игре»
  и «Требования». Задание без внятного «зачем» вернётся вопросом;
- **посмотреть очередь роли:** `bash pipeline/status.sh --for aimocap`;
- **принять работу:** `git pull`, затем
  `bash tools/asset_check/check.sh pipeline/delivery/<task-id>/v<N>` — паспорт ассета
  (габариты, полигонаж, материалы, скелеты, анимации; для звука — длительность, частота,
  моно/стерео, зацикливание) и замечания по спеке. Вердикт с цифрами — в раздел «Приёмка»;
- **принято** → `status: accepted`, файл остаётся в `done/`, ассет копируется в игру;
- **на переделку** → конкретные пункты в разделе «Правки», `revision+1`, `status: open`,
  файл возвращается в `open/`. Новое задание — только если нужен другой ассет;
- задания в `in_progress/` не трогать; в `blocked/` — отвечать на «Вопросы» и возвращать в `open/`;
- `QUEUE.md` руками не править — генерируется `bash pipeline/status.sh`.

Чего автопроверка не ловит и что надо смотреть самому: конвенция нормалей, проскальзывание
ног в циклах ходьбы, швы в зацикленном звуке, попадание в стиль.

**Картинки смотреть самому.** Claude Code открывает PNG/JPG как изображения, поэтому
`preview.png` из доставки и кадры из скриншот-харнесса надо **открывать и оценивать**,
а не пересылать пользователю со словами «посмотрите». К пользователю идти только за тем,
что действительно требует его вкуса и контекста (нравится ли, попадает ли в задумку),
и всегда с конкретным вопросом.

## Договорённости

- Язык общения и комментариев в коде — русский; идентификаторы и API — английские.
- JS: модули ES, табы, без сборщика и без `node_modules` — зависимости вендорятся.
- Никаких GUI-редакторов: всё правится текстом.
- `git` в PATH этой машины нет; он лежит в
  `%LOCALAPPDATA%\Programs\Git\cmd\git.exe` — добавлять в `$env:Path` перед вызовом.
- `bash` в PowerShell тоже нет: скрипты `pipeline/*.sh` запускать через Git Bash
  или переписывать вызов на PowerShell.
