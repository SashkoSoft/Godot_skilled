# Проект: разработка игры на Godot

>  **Если ты сессия-исполнитель** (делаешь контент, работаешь в `/loop`) — этот файл не про тебя.
> Твоя инструкция по роли:
> `houdini-assets` → **`pipeline/HOUDINI_LOOP.md`** ·
> `houdini-anim` → **`pipeline/HOUDINI_ANIM_LOOP.md`** ·
> `comfyui` → **`pipeline/COMFYUI_LOOP.md`**.
> Всё остальное в репозитории читать не нужно, трогать — тем более. Godot ставить не нужно.

## Движок

Godot **4.7-stable** лежит прямо в корне:
- `Godot_v4.7-stable_win64.exe` — GUI
- `Godot_v4.7-stable_win64_console.exe` — **для всех CLI-команд** (только он пишет в stdout)

Актуальный патч ветки на 2026-08-22 — 4.7.2-stable (обновление опционально, только багфиксы).

| `.claude/skills/godot-codefirst/` | скил: код-первый подход, старт проекта, экспорт, 3D-визуал, звук, производительность |

Скилы дополняют друг друга, оба выросли из реальных проектов (`ORIGIN.md` в каждом).
Чего в них **нет** ни в одном: 2D/TileMap-пайплайн, анимации и скелеты, импорт `.glb`,
`NavigationAgent3D`, экспорт под Web/Android/Linux, выделенный сервер. На этих темах
опираться на `docs/`, а не достраивать по аналогии со скилами. Если два текста расходятся —
верить тому, где есть замер или воспроизводимый симптом.

## Контент делают три сессии-исполнителя

Ассеты приходят от отдельных сессий Claude Code, работающих в `/loop`, каждая в своём
клоне репозитория. Обмен — только через файлы в `pipeline/` (протокол — `pipeline/README.md`).

| Роль (`assignee`) | Что делает | Спека |
|---|---|---|
| `houdini-assets` | модели, текстуры, материалы, VFX | `pipeline/ASSET_SPEC.md` |
| `houdini-anim` | скелетные анимации (KineFX, APEX) | `pipeline/ANIM_SPEC.md` |
| `comfyui` | изображения, флипбуки, UI, концепты, SFX | `pipeline/ASSET_SPEC.md`, `pipeline/AUDIO_SPEC.md` |

Со стороны этой сессии:

- **создать задание:** `bash pipeline/new_task.sh <роль> <slug> "<заголовок>"` — подставит
  свободный номер, `assignee` и ссылку на нужную спеку; дальше описать «Зачем это в игре»
  и «Требования». Задание без внятного «зачем» вернётся вопросом;
- **посмотреть очередь роли:** `bash pipeline/status.sh --for houdini-anim`;
- **принять работу:** `git pull`, затем
  `bash tools/asset_check/check.sh pipeline/delivery/<task-id>/v<N>` — паспорт ассета
  (габариты, полигонаж, материалы, скелеты, анимации; для звука — длительность, частота,
  моно/стерео, зацикливание) и замечания по спеке. Вердикт с цифрами — в раздел «Приёмка»;
- **принято** → `status: accepted`, файл остаётся в `done/`, ассет копируется в игру;
- **на переделку** → конкретные пункты в разделе «Правки», `revision+1`, `status: open`,
  файл возвращается в `open/`. Новое задание — только если нужен другой ассет;
- задания в `in_progress/` не трогать; в `blocked/` — отвечать на «Вопросы» и возвращать в `open/`;
- `QUEUE.md` руками не править — генерируется `bash pipeline/status.sh`.

Чего автопроверка не ловит и что надо смотреть самому: конвенция нормалей, проскальзывание
ног в циклах ходьбы, швы в зацикленном звуке, попадание в стиль.

## Редактор Godot не открывается — никогда

Пользователь **не работает в GUI-редакторе**. Значит:
- Вся сцена строится из GDScript (подход скила `godot-codefirst`), `.tscn` — заглушка.
- Никаких инструкций вида «зайди в Проект → Настройки и поставь галку». Всё, что настраивается, —
  правится в `project.godot` / `export_presets.cfg` текстом.
- Импорт ассетов и генерация `.import` — через `--headless --import`, а не открытием редактора.
- Действия, требующие GUI, надо решать обходным путём и не перекладывать на пользователя.

### Шаблоны экспорта

Установлены в `%APPDATA%\Godot\export_templates\4.7.stable\` — **только Windows x86_64**
(debug/release, обычный и console). Сборка `.exe` работает, GUI не нужен.

Если понадобится Web/Linux/Android — скачать полный набор и распаковать без редактора:

```bash
curl -L -o templates.tpz \
  https://github.com/godotengine/godot/releases/download/4.7-stable/Godot_v4.7-stable_export_templates.tpz
# внутри .tpz (это zip) все файлы лежат в папке templates/ — их содержимое кладётся в
# %APPDATA%/Godot/export_templates/4.7.stable/
unzip -j templates.tpz 'templates/*' -d "$APPDATA/Godot/export_templates/4.7.stable/"
```

Архив ~1.3 ГБ — качать только по необходимости и предупредив пользователя.

## Как проверять свою работу

Не сваливать проверку на пользователя. После каждой существенной правки:

```bash
./Godot_v4.7-stable_win64_console.exe --headless --path <проект> --quit-after 60
```

Это ловит ошибки парсинга, опечатки в API и падения в `_ready()`. Headless не проверяет
только визуал и звук — про них честно просить посмотреть, описав, что оценить.

## Договорённости

- Язык общения и комментариев в коде — русский; идентификаторы и API — английские.
- Стиль GDScript — официальный (`tutorials/scripting/gdscript/gdscript_styleguide.rst`):
  табы, `snake_case`, статическая типизация.
- Подход к сборке сцен — см. скил `godot-codefirst` (сцена строится из кода, `.tscn` — заглушка),
  если пользователь не сказал иначе.
