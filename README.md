# Godot_skilled

Рабочая база для разработки игр на **Godot 4.7** из-под Claude Code: документация,
накопленные скилы и пайплайн обмена ассетами с Houdini-сессией.

## Структура

| Путь | Что это |
|---|---|
| `CLAUDE.md` | правила работы для сессии: версия движка, где что искать, как себя проверять |
| `docs/` | база знаний по Godot: карта, выжимки, скрипты подтягивания мануала |
| `.claude/skills/` | скилы, подключённые к проекту (`godot-codefirst`, `godot-selfcheck-3d`) |
| `External_sessions_skills/` | те же скилы «как пришли» из прошлых сессий — источник |
| `pipeline/` | обмен заданиями и ассетами с Houdini-сессией |

## После клонирования

Два больших компонента намеренно **не хранятся в git** и подтягиваются локально.

**1. Документация Godot (~970 МБ)** — официальный мануал ветки 4.7 и демо-проекты:

```bash
bash docs/fetch_docs.sh
# или на Windows:
powershell -ExecutionPolicy Bypass -File docs\fetch_docs.ps1
```

**2. Сам движок** — `Godot_v4.7-stable_win64.exe` и `..._win64_console.exe` кладутся
в корень репозитория вручную (бинарник 178 МБ больше лимита GitHub на файл).
Скачивается со страницы релизов `godotengine/godot`, версия должна совпадать с той,
на которую настроен `docs/fetch_docs.sh` (ветка `4.7`).

Для CLI всегда используется `*_console.exe` — только он пишет в stdout.

## Пайплайн ассетов

Ассеты (текстуры, модели, эффекты) делает отдельная Houdini-сессия, работающая в `/loop`.
Обмен — через файлы в `pipeline/`:

- задания кладутся в `pipeline/tasks/open/`, папка задания = его статус;
- готовые файлы приходят в `pipeline/delivery/<task-id>/` с отчётом `RESULT.md`;
- требования к форматам — `pipeline/ASSET_SPEC.md`, протокол — `pipeline/README.md`,
  инструкция для лупа — `pipeline/HOUDINI_LOOP.md`.
