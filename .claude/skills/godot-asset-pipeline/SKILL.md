# Приёмка внешних .glb-ассетов в Godot

Собран на проекте, где три отдельные Claude-сессии (Houdini-модели,
Houdini-анимации, ComfyUI-текстуры) поставляют ассеты в общий `pipeline/`,
а сессия с Godot их принимает и ставит в сцену. Все грабли — из разбора
конкретных расхождений, не из документации Godot (см. `ORIGIN.md`).

## Главное правило

**«Принято» в тексте задания — не факт, это утверждение, которое надо
перепроверить.** Дважды в этом проекте запись приёмки говорила «стоит в
игре», хотя файлы не копировались в проект вообще. Причина всегда одна:
проверяли по превью доставки или по описанию, не по самой работающей игре.
Три проверки покрывают почти все ошибки — и все три автоматические,
без разглядывания рендера:

| Проверка | Что ловит | Подробнее |
|---|---|---|
| Текстура физически привязана? | `.glb` ссылается на PNG, которого нет рядом | `references/glb-import.md` |
| Показатели меша (полигоны/нормали/UV) | вырожденные грани, растянутая развёртка | `references/numeric-verification.md` |
| Файл реально скопирован и используется в коде? | «принято», но не поставлено в сцену | `references/pipeline-trust.md` |

## Живая галерея вместо ручного перебора

Когда моделей и материалов набирается несколько десятков, смотреть их по
одной в редакторе — не вариант. `references/asset-gallery.md` — как собрать
статическую HTML-страницу с настоящими вращаемыми 3D-превью
(`<model-viewer>`, не скриншоты) и числовыми показателями рядом, и как
опубликовать её отдельно от исходников игры через orphan-ветку GitHub Pages.

## Что читать дальше

| Файл | Когда |
|---|---|
| `references/glb-import.md` | модель без текстуры, хотя PNG на месте; когда нужен headless-режим, а когда обязательно GPU-окно |
| `references/numeric-verification.md` | как проверить форму/развёртку/текстуру числом; частые ложные тревоги в таких проверках |
| `references/asset-gallery.md` | галерея с живым вращением моделей, локальный сервер, публикация на GitHub Pages без исходников игры |
| `references/pipeline-trust.md` | почему «принято» ≠ «в игре», как сверять автоматически |

## Рабочие привычки

- Любая новая доставка: сначала числом (`--texcheck`-подобная проверка), потом
  разглядыванием рендера — не наоборот. Разброс (σ) яркости в области UV —
  дешёвый и надёжный признак «текстура реально есть», а не заглушка.
- После копирования нового `.glb`+текстур в проект — headless-импорт
  (`--headless --path <проект> --import`), и если старая проверка почему-то
  всё ещё не видит текстуру — удалить `.import`-файл именно этой модели и
  повторить: Godot не переимпортирует зависимый `.glb` только потому, что
  файл, на который он ссылается, наконец появился.
- Перед словом «принято» в записи задания — прогнать проверку, которая
  сверяет файловую систему, а не полагаться на память или на превью.
