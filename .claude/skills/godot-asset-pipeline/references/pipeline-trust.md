# «Принято» ≠ «в игре»

## Расхождение, из-за которого это написано

В записи приёмки двух отдельных задач было буквально написано «стоит в
игре» и «стоит на месте прежней заглушки». Ни то, ни другое не было правдой:
проверка git-истории показала, что коммит доставки трогал только файл-очередь
пайплайна — сами ассеты в папку игры никогда не копировались, и в коде на
них нет ни одной ссылки. Кто-то принял задание по качеству ассета
(модели/текстуры хорошие) и написал приёмку так, будто интеграция уже
сделана — а она не была.

Вывод общий, не про эти две задачи: **раздел «Приёмка» — свободный текст,
его пишет и читает один и тот же тип сессии, и он может быть неточным без
злого умысла**, просто потому что «оценили ассет» и «поставили в сцену» —
разные действия, а естественный язык не заставляет их различать. Доверять
можно только тому, что проверяется автоматически.

## Три факта, которые нужно проверять по отдельности

«Задача принята» на самом деле утверждает три разные вещи, и каждая может
быть неправдой независимо от других:

1. **Ассет качественный** — то, что проверяют числовые тесты из
   `numeric-verification.md`.
2. **Файлы скопированы** в проект игры (а не только лежат в папке доставки
   пайплайна).
3. **Ассет используется** — на него есть ссылка в коде сцены, он реально
   отрисовывается, а не просто присутствует на диске рядом с остальными.

Пример из практики: перила для лестницы были численно проверены и
физически скопированы в проект (пункты 1 и 2 — правда), но ни разу не
упомянуты в коде, который строит лестницу (пункт 3 — неправда). Это не
ошибка приёмки — интеграция была осознанно отложена (нашлась причина: сцена,
где стоит лестница, сама себя описывает как «только примитивы», это другой
слой, не витрина ассетов) — но узнать это можно было только проверкой,
не из текста задания.

## Автоматическая сверка вместо доверия записи

Для каждой сданной задачи, а не только для той, что сейчас на глазах:

```python
# 1. взять список файлов из последней версии доставки (pipeline/delivery/task-*/vN/),
#    кроме preview.png, RESULT.md, source/
# 2. для каждого файла — есть ли файл с таким же именем (без учёта суффикса
#    разрешения типа _1k/_2k/_512 — легитимный даунскейл при интеграции
#    не должен считаться пропажей) где-нибудь под папкой ассетов игры
# 3. упоминается ли имя файла (без расширения) хоть в одном исходнике сцены
```

Пункт 2 без нормализации разрешения даёт ложные тревоги: если материал
был перепакован из 2k в 1k при интеграции, точное совпадение имени файла
не найдёт его и ошибочно объявит пропавшим. Сравнивать нужно по имени без
суффикса разрешения, не по байтам и не по точному имени файла.

Результат стоит держать **в двух местах одновременно**: как generated-файл
в репозитории (для разбора руками, с git-историей) и как маленький JSON,
который читает сама галерея (см. `asset-gallery.md`) — баннер прямо на
странице «принято, но не в игре, вот список» не даёт следующей сессии
повторить тот же не глядя-«принято».

## Когда писать вердикт

Прогонять сверку **до** того, как написать «принято» в разделе приёмки, а
не после того, как что-то показалось подозрительным. Дешевле проверить
всегда, чем помнить, в каких случаях проверка была нужна.
