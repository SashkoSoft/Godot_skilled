# Пропы квартала правилами (web: fences.js, poles.js, curbs.js, slabs.js, rocks.js, playground.js)

Общее: всё ставится ОТ ДАННЫХ квартала (`district.json`), не руками по месту. Правило
пишется один раз и работает в любом квартале, в том числе сгенерированном. В JSON —
только параметры (шаг, отступ, доли), в коде — логика.

## Забор по контуру участка (`areas[].fence`)
- Плиты встык по краям прямоугольника, лицом наружу; калитка — пропуск плиты
  рядом с `gate`. Длина края делится на целое число плит (подгонка масштабом ±).
- Разнообразие: варианты износа по хешу позиции + набор износа шейдером (у каждой
  плиты своя смесь весов ±0.15) + каждая пятая чуть завалена (1–2°).
- Масштаб модели — полем в описании вида (`scale`, `wall` для координат стены).

## Опоры и провода (`poles`)
- Линия: точки вдоль улицы с шагом ≤ step у кромки со стороны двора; перекрёстки и
  дома РВУТ линию; на концах — концевая (подкос в сторону линии: у последней опоры
  линия уходит назад — развернуть). Фонарь через одну, вылет — к дороге (разворот
  на 180°, если +X модели смотрит от дороги).
- Провода: Wire_n → Wire_n соседней опоры; пару искать по ярусу (y) и стороне
  линии, а не по номеру — концевая развёрнута, её точки зеркальны. Провис —
  парабола 4·sag·span·t(1−t), при 1–2 % неотличима от цепной.
- Сверху линии толщиной в пиксель читаются грубо — для близких планов нужна лента.

## Бордюр (`curbs.js`) — тысячи кусков → экземпляры
- Раскладка вдоль кромки проезжей части, обе стороны, обход по +X модели; хвост —
  половинками. Перекрёсток: бровка кончается у кромки поперечной дороги.
- Въезды: конец проезда в полосе тротуара → ramp_down → low×N → ramp_up.
  Переходы/остановки: белый/чёрный через один. Обычные — bare a/b/c + редкий скол,
  ±0.5° и 0–1 см.
- InstancedMesh на (вид, LOD, часть меша), ступень у каждого камня своя,
  пересчёт только при сдвиге камеры.
- **Размеры по ГОСТу читать внимательно**: БР 100.30.15 — 1000×300×150, где 300 —
  ВЫСОТА, толщина 0.15. Тротуар — вплотную к тылу камня, иначе щель видна полосой.

## Плиты дорожек (`slabs`)
- Ряды вдоль отрезка: поперёк — целые плиты, вдоль — шаг плита+шов. У каждой своя
  судьба от хеша: шов (пятнами «старости»), просадка, перекос, корни ближнего
  дерева (подъём и наклон от ствола), выпавшая (видна земля), расколотая.
- Не класть на дома, асфальт улиц и проездов, площадки с покрытием; на углах
  ломаной — не дублировать (занятые места).
- Под плитами коробки дорожки НЕТ — в швах и проёмах земля пола.
- Разные текстуры: номер варианта в атрибуте экземпляра; пока наборов нет — сдвиг
  и поворот ×90° куска общей текстуры + свой оттенок.
- Фаска на LOD0 (скошенная кромка ловит свет). UV у каждой грани — в её плоскости
  (иначе на боковинах текстура тянется полосами). LOD без перестановки экземпляров:
  нулевая матрица в ненужной ступени (атрибуты привязаны к номеру).

## Камешки вблизи (`rocks.js`)
- Точки один раз по карте пола (щебень/стыки → галька, крошка/куски → камни),
  детерминированно, в корзины 8 м; рисуются только до 25 м (LOD0 до 12), выше 25 м
  камеры — вовсе нет. Плотность на ячейку 0.5 м — доли единицы, иначе сплошная галька.

## Площадка (`areas[].equipment`)
- Список { item, at от центра, rot°, scale } — раскладка данными. Подвижные узлы
  двигать мягко (карусель ползёт по ветру, качели ±7°); брошенное (балансир) — в
  крайнем положении, без движения.

## Ловушка glTF от gltfpack (_web.glb)
Позиции квантованы, **масштаб и сдвиг лежат в узле**. Брать `mesh.geometry` без
`matrixWorld` нельзя — форма огромная/не на месте. Всегда: `updateMatrixWorld`,
клон геометрии, квантованные атрибуты во float, `applyMatrix4(mesh.matrixWorld)`,
при необходимости — нормировать по габариту.
