# Свет и рендер интерьера в Godot 4.7 из кода

Собрано на реальной задаче: две квартиры панельного дома, стены 2.84 м,
изометрическая камера сверху-сбоку, вся сцена строится в `_ready` из `BoxMesh`.
Числа взяты из официальных демо в `docs/godot-demo-projects/3d/`, а не подобраны
на глаз.

## Какой GI применим к сцене, собранной из кода

| | печётся из кода | берёт PrimitiveMesh | вердикт |
|---|---|---|---|
| **LightmapGI** | нет, только в редакторе | **нет** | отпадает |
| **VoxelGI** | **да, и в собранной игре** | да | единственный вариант с бейком |
| **SDFGI** | бейк не нужен | да | для больших сцен |

`class_lightmapgi.rst` прямо говорит: запекание доступно только в редакторе,
поэтому LightmapGI не годится для процедурных уровней; и отдельно — что
`PrimitiveMesh` не запекается, так как не хранит UV2. То есть отпадает дважды.

VoxelGI печётся так:

```gdscript
var gi := VoxelGI.new()
gi.subdiv = VoxelGI.SUBDIV_256      # ячейка должна быть тоньше стены
gi.size = Vector3(11, 4, 9)         # плотно по квартире
add_child(gi)
await get_tree().process_frame      # вся геометрия и свет уже в дереве
gi.bake()
gi.data.interior = true             # не тянуть свет неба внутрь
```

`gi.data` появляется только **после** `bake()`. Геометрия должна быть готова —
иначе `call_deferred("bake")`. UV2 для VoxelGI не нужен, нужен только
`gi_mode = GI_MODE_STATIC` (это дефолт) и `StandardMaterial3D`: меши на
`ShaderMaterial` VoxelGI считает **чёрными**, они работают лишь как заслонки.

Размер ячейки = `max(size) / (128 << subdiv)`. При стенах 0.1 м и боксе 20 м
`SUBDIV_128` даёт 0.156 м — стены протекут. Нужен либо `SUBDIV_256`, либо
несколько узлов поменьше. Больше 8 VoxelGI в кадре нельзя, смешиваются только
два на пиксель.

**Но:** на камере, которая смотрит в открытую сверху планировку, VoxelGI может
сделать хуже. У нас перекрытие закрывает верх, `interior = true` отрезает небо,
и комнаты уходят в черноту. Оставили за флагом `--gi`.

## Значения из демо

Тонирование **AgX** (`TONE_MAPPER_AGX`) стоит во всех шести просмотренных демо.

Солнце (`physical_light_camera_units`, единственный чисто интерьерный сетап):

```gdscript
sun.light_angular_distance = 0.5
sun.light_bake_mode = Light3D.BAKE_STATIC
sun.shadow_blur = 1.8
sun.directional_shadow_mode = DirectionalLight3D.SHADOW_ORTHOGONAL
sun.directional_shadow_fade_start = 1.0
sun.directional_shadow_max_distance = 30.0     # под размер сцены
```

**Один сплит, а не каскады.** Во всех камерных демо (15, 17, 32 м) стоит
`SHADOW_ORTHOGONAL`: в замкнутой сцене PSSM даёт только швы и расход.

`shadow_bias` привязан к разрешению атласа теней (таблица из
`graphics_settings/settings.gd`):

| атлас | bias |
|---|---|
| 512 | 0.06 |
| 1024 | 0.04 |
| 2048 | 0.03 |
| 4096 | 0.02 |
| 8192 | 0.01 |

```gdscript
RenderingServer.directional_shadow_atlas_set_size(8192, true)
get_viewport().positional_shadow_atlas_size = 4096
```

Точечный свет — во всём `lights_and_shadows` стоит **`shadow_normal_bias = 4.0`**
вместо дефолтных 2.0. Мануал: поднимать нормальный bias предпочтительнее, чем
обычный, — он не даёт peter-panning, ценой чуть более тонкой тени.

Environment: `ssao_intensity = 1.0` (демо понижает с дефолтных 2.0),
`ambient_light_sky_contribution` около 0.5–0.65, иначе затенённое отдаёт синевой.

## Ловушки, на которых потеряно время

**Точечная рябь по полу — это не GI и не тени, а блики от карты нормалей.**
В наборах ORM зелёный канал местами тёмный, шероховатость падает, бетон
становится глянцевым и искрит по нормали. Лечится так:

```gdscript
# шероховатость и металличность из ORM не брать, держать матовость постоянной
m.roughness = 0.92
m.metallic_specular = 0.15     # в 4.x свойство называется так, не "specular"
```

На **полах** карту нормалей лучше не ставить вовсе: при свете лампы под
скользящим углом она даёт ту же искру.

**Невидимая крыша.** Без перекрытия солнце и лампы светят в комнаты сверху,
теней от стен нет, интерьер выглядит открытой коробкой. Но и рисовать её
нельзя — не видно планировку. Решение:

```gdscript
mi.cast_shadow = GeometryInstance3D.SHADOW_CASTING_SETTING_SHADOWS_ONLY
```

**Трипланарная развёртка в метрах** — обязательна, если геометрия собрана из
боксов разного размера: иначе на стене 5 м и на откосе 0.2 м рисунок разного
масштаба.

```gdscript
m.uv1_triplanar = true
m.uv1_scale = Vector3.ONE * 0.25      # 0.25 ≈ тайл на 4 м
```

**Затухание точечного света.** `omni_attenuation = 1.0` даёт ровную заливку, но
свет растекается в соседнюю комнату; 2.0 (как в демо) — быстрый спад и яркое
пятно под лампой. Рабочий компромисс для комнаты 3 × 5: `attenuation 1.8`,
`energy 4.2`, `range = max(w, d) * 1.6 + 4.0`. Дальность обязательно
увеличивать вместе с затуханием, иначе свет обрывается у стен.

**Свет через окно считается по геометрии.** Прозрачный материал тень не
пропускает: чтобы солнце попало в комнату, окно должно быть **дыркой в стене**
(подоконная часть, перемычка, откосы), а не боксом со стеклянным материалом.

**Проверка, что помещение вообще освещено.** Однажды комнаты были чёрными не
из-за света: жилые блоки просто не попали в список помещений при выгрузке, и у
них не было ни пола, ни лампы. Прежде чем крутить яркость — посчитать, сколько
источников встало и на какие блоки.

## Физические единицы

`use_physical_light_units` со всей строгостью (солнце 100000 lux, лампа 800 lm,
`CameraAttributesPhysical` с диафрагмой 2–4 для интерьера) включать не
обязательно: они принудительно включают DoF, а для изометрии он не нужен. Если
включать — `CameraAttributes` обязан висеть на `WorldEnvironment`, иначе кадр
будет пересвечен.

## Показать источники

Полезный отладочный режим: пройти по детям, для каждого `OmniLight3D` поставить
неосвещаемый светящийся шарик на его позицию. Шар радиуса действия рисовать не
стоит — на общем плане он заливает весь кадр, дальность понятнее подписью.
