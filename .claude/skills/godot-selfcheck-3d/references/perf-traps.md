# Ловушки производительности в 3D-сцене со светом

Общая техника оптимизации (MultiMesh, батчинг, LOD, порядок действий при
просадке) — в `references/performance.md` скила `godot-codefirst`. Здесь четыре
ловушки, где кадр умирает не от количества объектов, а от одной строчки.

## Метрика, по которой видно ловушку

```gdscript
print("PERF fps=%d process=%.2fms objects=%d prims=%d draws=%d" % [
    Engine.get_frames_per_second(),
    Performance.get_monitor(Performance.TIME_PROCESS) * 1000.0,
    int(Performance.get_monitor(Performance.RENDER_TOTAL_OBJECTS_IN_FRAME)),
    int(Performance.get_monitor(Performance.RENDER_TOTAL_PRIMITIVES_IN_FRAME)),
    int(Performance.get_monitor(Performance.RENDER_TOTAL_DRAW_CALLS_IN_FRAME))])
```

`prims` — треугольники **за кадр**, а не в сцене. Скачок в 10–100 раз при
неизменной модели означает, что геометрия рисуется многократно: тени или
прозрачность. Печатай эту строку из скриншот-харнесса (FPS в неактивном окне
занижен, а `prims` — честный).

## 1. Движущийся кастер теней у монолитного меша

Уровень собран одним большим мешем. Любой **движущийся** источник света с
тенями — или движущийся объект, кидающий тень, в радиусе стационарной лампы —
заставляет перерисовывать весь меш в грани кубической карты теней каждый кадр:
**227K prims → 12.9M**.

- свет у ботов, снарядов, вспышек — `shadow_enabled = false`;
- мелкие сущности (призы, следы, глаза, трейлы) —
  `cast_shadow = SHADOW_CASTING_SETTING_OFF`;
- транзиентная вспышка в точке попадания диртит кэш теней всех соседних
  статичных ламп — тоже без теней;
- статичный декор тени кидать может: он не двигается, кэш не инвалидируется.

Тени остаются у солнца, фонаря игрока и стационарных ламп.

## 2. Обрыв на прозрачных квадах

Больше ~100 прозрачных плоскостей (наклейки, билборды, alpha-scissor листва) —
`prims` 3.4M → 26.7M: отдельный проход с сортировкой и без раннего z-отсечения.
Порог нелинейный: при 40 штуках чисто, при 150 катастрофа. Лечится
непрозрачным материалом с реальной геометрией либо снижением плотности —
и **плотность не задирай, не сняв PERF**.

## 3. Тени десятка точечных ламп на слабой видеокарте

Главный убийца кадра на интегрированной графике: 6 FPS против 180 на дискретке.
Режим «слабый ПК» (тумблер + автовключение при среднем FPS < 35 через 5–6 с
после старта, с сообщением на экране):

```gdscript
vp.scaling_3d_mode = Viewport.SCALING_3D_MODE_FSR
vp.scaling_3d_scale = 0.67
vp.positional_shadow_atlas_size = 2048
RenderingServer.positional_soft_shadow_filter_set_quality(
    RenderingServer.SHADOW_QUALITY_SOFT_VERY_LOW)
# + лампы без теней, объёмный туман / SSAO / glow выключены
```

Порядок отключения по цене: тени точечных ламп → объёмный туман → SSAO →
glow → разрешение рендера и атлас теней. Фонарик и солнце оставь: без них
темно и непонятно.

Тумблеры обязаны переприменяться после перестройки мира — новые ноды
рождаются с дефолтами.

## 4. Стоимость генерации

GDScript медленный на тяжёлых циклах: генерация уровня с высокой детализацией
у нас ~20 с. Что помогает без C#/GDExtension: ползунок «Детализация» в UI
(выкинуть работу, а не оптимизировать), `Packed*Array` в горячих циклах,
один меш вместо ноды на элемент, кэш в `user://` для всего, что не зависит от
сида. Дольше пары секунд — показывай прогресс, иначе это выглядит как
зависание; а в сетевой игре блокирующий цикл ещё и рвёт линк по таймауту.
