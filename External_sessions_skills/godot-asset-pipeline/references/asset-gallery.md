# Живая галерея библиотеки ассетов

Когда моделей и материалов набирается несколько десятков, «открыть в
редакторе и посмотреть» перестаёт работать как процесс приёмки. Решение —
одна статическая HTML-страница с настоящими вращаемыми 3D-превью и числами
рядом, а не набор скриншотов, которые устаревают при следующей правке.

## Модели — живые, не скриншоты

`<model-viewer>` (Google, `@google/model-viewer`, BSD-3-Clause) — веб-
компонент, который сам грузит `.glb` и даёт вращать/зумить мышью без
всякого WebGL-кода с нуля:

```html
<script type="module" src="model-viewer.min.js"></script>
<model-viewer src="models/chair.glb" camera-controls
    environment-image="neutral" exposure="1.0" loading="lazy"></model-viewer>
```

Скачать библиотеку **локально**, не подключать через CDN — тогда галерея
работает офлайн и не зависит от аптайма чужого хостинга. Материалы (просто
PNG-текстуры: albedo/normal/orm без меша) не нуждаются в WebGL вообще,
достаточно `<img>` — но если у материала несколько карт, стоит дать клик по
маленькому превью normal/orm, чтобы подставить её в большую картинку:
изначально показывать только albedo и не давать посмотреть остальные карты
крупно — сам себя обкрадывать в возможностях проверки.

## file:// не работает — только http://

`fetch()` (за данными JSON) и загрузка `.glb` внутри `<model-viewer>` **обе
блокируются CORS**, если страница открыта напрямую как `file://путь.html`.
Нужен настоящий локальный сервер:

```bash
python -m http.server 8765 --bind 127.0.0.1
```

и открывать `http://localhost:8765/...`, не двойным кликом по файлу.

## Данные для галереи — считать один раз, не при каждой правке HTML

Сама HTML-страница должна быть тупой: читает готовый JSON (список моделей
с цифрами вроде полигонажа/привязки текстуры/σ, список материалов с
файлами карт) и просто рисует карточки. Генерация JSON — отдельный шаг
(headless-проход движка по всей папке моделей + простой скрипт-обход папки
текстур, без движка). Разделение важно: обновление библиотеки — это
пересчёт JSON, а не правка HTML каждый раз.

**Не забыть текстуры, которые лежат РЯДОМ с моделью**, а не в общей папке
материалов — если экспорт использует внешние `uri` (см.
`glb-import.md`), эти PNG физически лежат в той же папке, что и `.glb`, и
скрипт, который сканирует «только папку текстур», их пропустит — модели в
галерее будут выглядеть без текстуры даже при полностью рабочей игре.

**Разные категории — разная структура на диске.** Если материалы организо-
ваны «одна папка — один материал» (albedo+normal+orm вместе), а декали или
другая категория свалены в одну папку вперемешку (десяток НЕсвязанных
картинок в одном месте) — группировать по папке для второго случая нельзя,
получится один «материал» из семи чужих друг другу картинок. Правильно —
группировать по общему префиксу имени файла (снять суффикс `_albedo`/
`_normal`/`_orm`/разрешение), независимо от того, в одной они папке или нет.

## Публикация отдельно от исходников игры

Если нужно дать ссылку на галерею, не выкладывая исходный код игры/
пайплайна в общий доступ (или просто отдельно от основной ветки, которая
ещё не готова к пушу) — **orphan-ветка** в том же репозитории, а не отдельный
проект:

```bash
git worktree add --orphan -b gh-pages ../gh-pages-worktree
```

Собрать в этот отдельный каталог только то, что нужно сайту (HTML,
библиотеку просмотрщика, сами `.glb`/картинки — без `.gd`-скриптов, без
пайплайн-данных), закоммитить и запушить **только эту ветку**:

```bash
git push origin gh-pages   # основная ветка не трогается вообще
```

`git worktree` держит эту ветку в отдельной папке на диске — редактировать
исходный репозиторий не нужно, и случайно закоммитить туда лишнее (историю
`main`, файлы исходников) физически нельзя, там их просто нет на диске.
GitHub Pages включается один раз в настройках репозитория (Settings → Pages
→ branch `gh-pages` / root) — это делает человек в браузере, токена на это
у сессии обычно нет.

Перед пушем — обязательно поднять именно эту собранную папку локальным
сервером и открыть в headless-браузере (Playwright/Chromium), проверив
консоль на 404: раскладка путей в отдельной ветке отличается от локальной
разработки (`../../game/assets/...` превращается в `assets/...`), и разница
в путях — самый частый источник битых ссылок именно на этом шаге.
