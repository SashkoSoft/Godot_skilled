# Мультиплеер: host-авторитарный ENet за один файл

Рабочая схема «сколько угодно игроков в комнате» без выделенного сервера:
хост = один из игроков, он же авторитет. Весь код умещается в одну ноду-модуль
(`net.gd`, ~1200 строк вместе с чатом и голосом).

## Каркас

```gdscript
# нода добавляется в main с ФИКСИРОВАННЫМ именем — путь Main/Net должен
# совпадать у всех пиров, иначе RPC не найдёт получателя
net.name = "Net"

func start_host() -> void:
    var peer := ENetMultiplayerPeer.new()
    if peer.create_server(PORT, 32) != OK: return
    multiplayer.multiplayer_peer = peer
    _connected = true                     # у хоста соединение готово сразу

func join(ip: String) -> void:
    var peer := ENetMultiplayerPeer.new()
    if peer.create_client(ip.strip_edges(), PORT) != OK: return
    multiplayer.multiplayer_peer = peer   # _connected ставится в connected_to_server
```

Сигналы: `peer_connected` / `peer_disconnected` (у хоста),
`connected_to_server` / `connection_failed` / `server_disconnected` (у клиента).

## Мир не пересылается — он детерминирован

Геометрию уровня по сети гонять не нужно. Хост шлёт **словарь параметров
генерации** (сид + значения ползунков), клиент строит тот же мир сам:

```gdscript
@rpc("authority", "call_remote", "reliable")
func rpc_world(p: Dictionary) -> void:
    main.apply_world_params(p)   # если параметры уже совпали — не перестраивать
```

Условие: все подсистемы сидируются от общего `gen_seed` (лампы `99+seed`,
ящики `155+seed`, декор `991+seed`) и нигде не используют глобальный `randf()`.
Бонус: клиент, запущенный с теми же дефолтами, не перестраивает мир вообще.

## Что реплицировать и как часто

| Что | Частота | Канал |
|---|---|---|
| позиции игроков | 15 Гц | `unreliable_ordered` |
| позиции ботов (хост → все) | 12 Гц | `unreliable_ordered` |
| снаряды-марионетки | 12 Гц | `unreliable_ordered` |
| спавн/смерть/подбор/чат | событие | `reliable` |
| полный снапшот (вход, реген) | событие | `reliable` |

Полный снапшот при входе и после каждой регенерации мира обязателен — иначе
опоздавший видит пустой уровень. В нём: боты (с типами и hp), призы, счёт,
летящие снаряды.

## Авторитет решает всё, клиент рисует

Подбор предмета, попадание, урон, смерть, спавн — **только на хосте**
(`if not is_host(): return`). Клиент шлёт намерение (`rpc_shoot`) и рисует
предсказание; хост подтверждает событием.

Физика — тоже только у авторитета. У клиентов те же тела висят как
замороженные puppet'ы (`freeze = true`, `collision_layer/mask = 0`) и
интерполируются к сетевым позициям. Иначе две симуляции разъедутся, и мяч
у каждого отскочит по-своему.

У ИИ-ботов на клиенте — режим `puppet`: логика выключена, интерполяция позиции
плюс зеркалирование состояния (цвет/свет/звук работают от него).

## Грабли, съеденные в реальном проекте

1. **RPC до завершения ENet-handshake** → ошибки в лог. Флаг `_connected`,
   ставится в `connected_to_server`; до него не слать ничего.
2. **Блокирующая генерация роняет линк.** Клиент 20 секунд строит лабиринт в
   одном кадре — ENet считает его мёртвым по таймауту. Лечится
   `enet_peer.set_timeout(64, 30000, 60000)` **на обеих сторонах** (или
   генерацией по кускам).
3. **`get_unique_id()` после закрытия пира** бросает ошибку — кэшируй id в
   переменную при подключении.
4. **Буквы в чате = хоткеи.** Гейт по фокусу поля ввода — иначе набранное
   сообщение одновременно бегает, стреляет и генерирует уровень.
5. **Двойной `server_disconnected`** — процедура teardown обязана быть
   идемпотентной.
6. **Перезапуск сцены (`R`) и «Сгенерировать» у клиента** — блокировать:
   в сети мир меняет только хост.
7. **Windows Firewall** спросит разрешение при первом хостинге — предупреди
   пользователя, иначе «не коннектится» без видимой причины.

## Проверка без второго человека

Флаги харнесса поднимают два инстанса на `127.0.0.1`:

```
Game.exe -- --mp-host --mp-name=Host
Game.exe -- --mp-join=127.0.0.1 --mp-name=Guest --shot=C:/tmp/guest.png
```

Смотреть: чистые логи с обеих сторон, счётчик игроков в HUD, кадр гостя с
аватаром хоста. Это ловит почти все ошибки RPC-путей и порядка вызовов.

## Чат и голос

- Текст: `LineEdit` + лог на 8 строк, гаснущий по таймеру; `reliable`.
- Голос (push-to-talk): микрофон → заглушённая шина `Record` +
  `AudioEffectCapture` → моно s16 на половинной частоте → `unreliable` RPC →
  `AudioStreamGenerator` **на аватаре говорящего** (голос слышен оттуда, где
  игрок стоит). Нужен `audio/driver/enable_input=true` в `project.godot`.
- Системные сообщения («хост перегенерировал мир», «включён режим слабого ПК»)
  тоже шли в чат — это бесплатный канал обратной связи с игроком.

## Аватары

Капсула + `Label3D` с именем + цвет по peer id из фиксированной палитры
(один и тот же цвет у всех пиров). Прятать аватар ближе ~0.5 м от камеры,
иначе он заливает экран. Позиционные шаги и фонарик у аватара — без теней
(см. `performance.md`).
